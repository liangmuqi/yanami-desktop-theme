# 操作说明

## 环境要求

- Windows 10 / 11，当前以 x64 环境开发和验证。
- 当前 Windows 用户已安装官方 Microsoft Store 包 `OpenAI.Codex`，并可正常使用 ChatGPT / Codex。
- Node.js 22+；安装器也会尝试使用官方客户端附带、版本满足要求的 Node。
- Windows PowerShell 5.1、Windows Script Host 和系统 .NET Framework C# 编译器可用。
- 不需要 API Key，不需要把账号密码交给本项目。

## 下载与预检

下载完整 ZIP 并解压到普通文件夹，不要只下载单个脚本。终端进入项目目录后，可先运行只读预检：

```powershell
powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\Install.ps1 -CheckOnly
```

预检不会关闭客户端、写入安装目录或注册任务。若检测到旧开发版本占用同名主题任务，请先关闭那个版本，再安装此包，避免两个加载器同时运行。

若下载文件被 Windows 标记为来自网络，请先确认来源，在 ZIP 文件属性中解除锁定后再解压。组织策略禁止脚本时，应遵守组织策略；本项目不修改机器的全局执行策略。

## 正式安装

1. 保存输入内容，并从客户端菜单完整退出；仅关闭窗口可能仍保留后台进程。
2. 双击 `Install.cmd`，在普通用户会话中运行。
3. 安装器发现当前官方包、校验签名、编译连接检查和统一启动程序，并注册当前用户后台任务。
4. 打开安装目录，右键 `ChatGPT.lnk` → 固定到开始，然后取消原先那个 ChatGPT 的固定。不要保留两个固定图标。
5. Nexus 中编辑已有 ChatGPT 项目，类型设为程序，目标直接改为安装目录内 `bin/ThemeEntry.exe`，图标使用 `bin/ChatGPT.ico`；清除原来的 AppsFolder / 旧版本目标。
6. 从替换后的固定图标启动。后台程序不会为了接入主题关闭或重启应用。

安装位置：`%LOCALAPPDATA%\YanamiDesktopTheme`。当前用户后台任务名称：`YanamiTheme-Recovery`。安装器只在此安装目录内生成 `ChatGPT.lnk`，不会自动新增桌面或开始菜单图标。Windows 需要通过界面执行固定操作。

如端口冲突，可在安装时指定其他本机高位端口：

```powershell
powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\Install.ps1 -Port 49439
```

未替换的商店 / 所有应用 / 搜索入口仍是官方直接入口。如果已经从这些入口打开，统一入口只唤回同一窗口，不会重启来强行加入主题。需要主题时请保存工作、完整退出一次，再从替换后的图标打开。仅点关闭窗口可能仍保留后台进程。

## 日常使用

- **外观**：选择白 / 墨，切换对应主题的人物。
- **启动动画**：手动重播；自动开屏按应用会话去重，未退出时再次唤回窗口不应重播。
- **显示八奈见 / 清晰度 / 呼吸动态**：控制人物显示。
- **开屏标识**：默认跟随当前产品，也可指定 Codex 或 ChatGPT。
- **点击人物**：读取当前本地 Codex 账户的共享用量。它不是 ChatGPT 全部模型用量的统一统计。

窄窗口可能收起人物，以保留输入空间。气泡允许稍微覆盖其他区域，点击气泡外部或按 Esc 可关闭。

## 更换本地素材

素材清单在 `assets/manifest.json`。保留已有 ID（`cutout`、`peace`、`crown`、`profile`、`scarf`、`sport`、`smile`），用自己有权使用的 PNG / WebP 替换相应文件，并同步清单文件名。

文件名只允许字母、数字、短横线以及 `.png` / `.webp` 后缀，单张不超过 10 MiB。人物已抠图、背景与白底协调时效果更好。本项目不自动生成或抠除背景。

## 卸载与更新

双击 `Uninstall.cmd`。脚本只处理安装目录所拥有的后台任务和加载器，不终止官方客户端，不修改原图标。若当前连接不可用，完整退出客户端后内存中的主题也会消失。

卸载后请取消主题入口的固定，并从“所有应用”重新固定官方 ChatGPT；Nexus 恢复为官方应用入口。卸载保留安装目录中的文件和 `state/` 诊断数据。确认无需备份后，可手动删除整个安装目录。更新前先备份自行替换的素材，运行旧版卸载，再使用新包安装。

客户端升级后，加载器会重新查找当前用户注册的官方商店包，校验包身份和可执行文件签名后更新连接路径。主题偏好、端口和原快捷方式保留；不会修改新客户端的安装文件。检测失败会暂停接入，未就绪时最多每 30 秒重新检查一次。界面结构或桥接协议变化仍可能需要适配。

## 日志与隐私

安装目录的 `state/` 保存当前机器上的路径、进程标识和诊断状态，它不应上传到公共仓库。提交反馈只需提供版本、入口、症状和必要的脱敏字段。

GitHub 上的源码包不包含原工作区日志、聊天截图、独立用户数据目录、修改后的安装包或账户数据。
